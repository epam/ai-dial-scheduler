# Phase 1 Data Model: Schedule & Run Persistence Tables

Derived from the spec's Key Entities and Functional Requirements, grounded in the research
decisions (R1–R8). Column types are the resolved PostgreSQL/SQLAlchemy types.

## Entity: Schedule → table `schedules`

Queryable business metadata for one APScheduler job. Extends `BaseSQLModel`
(inherits `created_at`, `updated_at`, auto `__tablename__` → `schedules`).

| Column | Type | Null | Default | Notes |
|--------|------|------|---------|-------|
| `id` | `VARCHAR(191)` | NO | — (app-supplied) | **PK**. Logically equals `apscheduler_jobs.id`. **No** FK to the engine table (logical link only). |
| `created_at` | `TIMESTAMPTZ` | NO | `now()` (server) | From `BaseSQLModel`. |
| `updated_at` | `TIMESTAMPTZ` | NO | `now()` (server, `onupdate now()`) | From `BaseSQLModel`. |
| `display_name` | `TEXT` (`String`) | NO | — | Human-readable name. |
| `created_by` | `TEXT` (`String`) | NO | — | Creator/owner identity. |
| `trigger` | `JSONB` | NO | — | Structured trigger definition. |
| `kwargs` | `JSONB` | NO | — | Structured call arguments. |

**Constraints**: `PK_schedules` on `id`.

**Relationships**: one-to-many → `ScheduleRun` (via `schedule_runs.schedule_id`). Deletion
blocked while runs exist (enforced on the child FK, R7).

**Validation rules** (FR-002/003/004): `id` non-empty and ≤ 191 chars; `display_name`,
`created_by` non-empty; `trigger`, `kwargs` present (objects).

## Entity: ScheduleRun → table `schedule_runs`

One execution attempt of a schedule. Extends `BaseSQLModel`
(auto `__tablename__` → `schedule_runs`).

| Column | Type | Null | Default | Notes |
|--------|------|------|---------|-------|
| `id` | `UUID` | NO | `uuid4()` (app-side) | **PK**, globally unique, independent of schedule. |
| `created_at` | `TIMESTAMPTZ` | NO | `now()` (server) | From `BaseSQLModel`. |
| `updated_at` | `TIMESTAMPTZ` | NO | `now()` (server, `onupdate now()`) | From `BaseSQLModel`. |
| `end_time` | `TIMESTAMPTZ` | **YES** | `NULL` | Empty while `in_progress` (FR-011). |
| `status` | `TEXT` (`String`) | NO | — | One of `success`/`error`/`in_progress`/`missed`, enforced by CHECK. |
| `result` | `JSONB` | **YES** | `NULL` | Result payload; absent for runs not yet finished. |
| `schedule_id` | `VARCHAR(191)` | NO | — | **FK** → `schedules.id`, `ON DELETE RESTRICT`; **indexed**. |
| `schedule_snapshot` | `JSONB` | NO | — | Point-in-time `{display_name, trigger, kwargs}` (FR-012). |

**Constraints**:
- `PK_schedule_runs` on `id`.
- `FK_schedule_runs_schedule_id_schedules`: `schedule_id` → `schedules.id`,
  `ondelete="RESTRICT"` (R7, FR-013/FR-014).
- `CK_schedule_runs_status`: `status IN ('success','error','in_progress','missed')`
  (R4, FR-010).
- `IX_schedule_runs_schedule_id`: index on `schedule_id` (R7).

**State transitions** (status; informational — not DB-enforced beyond the value set):

```text
in_progress ──▶ success
            ├──▶ error
missed (terminal; run never started in time)
```

`end_time` and `result` are expected to be populated on transition to `success`/`error`;
`in_progress` rows have `end_time = NULL`.

**Validation rules**: `status` ∈ the four values (DB CHECK); `schedule_id` references an
existing schedule (DB FK); `schedule_snapshot` present.

## External reference: `apscheduler_jobs` (NOT managed)

Read-only Core `Table` on a **separate metadata** (R2) — never emitted by our migrations
(FR-017). Only the columns needed for the join are declared:

| Column | Type | Null | Notes |
|--------|------|------|-------|
| `id` | `VARCHAR(191)` | NO | Engine job id; join key = `schedules.id`. |
| `next_run_time` | `DOUBLE PRECISION` | YES | Epoch seconds; `NULL` when paused. |

Owned and created by APScheduler's `SQLAlchemyJobStore`. Not in `BaseSQLModel.metadata`; not
in scope to create/alter/drop.

## Join contract (FR-005/FR-006, SC-001)

```text
schedules
  LEFT OUTER JOIN apscheduler_jobs ON schedules.id = apscheduler_jobs.id
SELECT schedules.*, apscheduler_jobs.next_run_time AS next_run_time
```

LEFT OUTER JOIN guarantees every `schedules` row is returned even when no engine row exists
or `next_run_time` is `NULL` (FR-006). The returned `next_run_time` is a nullable float
epoch (conversion to datetime is a downstream concern).

## Migration outcome (FR-016/FR-018, SC-005)

A single Alembic **autogenerated** revision whose:
- **upgrade** issues `op.create_table("schedules", ...)` and
  `op.create_table("schedule_runs", ...)` including the PK, the named CHECK, the FK
  (`ON DELETE RESTRICT`), the index, and `op.create_index(...)` for `schedule_id`.
- **downgrade** issues `op.drop_index(...)` + `op.drop_table("schedule_runs")` then
  `op.drop_table("schedules")` — removing everything (no orphaned types, since no native
  enum is used).
- Contains **no** reference to `apscheduler_jobs` (excluded via `_UNMANAGED_TABLES` and the
  separate metadata) and requires **no manual edits**.
